# Symbol files (.ecadsym)

Each symbol is a standalone UTF-8 JSON `.ecadsym` file (`.json` is also accepted). A library is simply a directory of these files, with no manifest or combined library file:

```text
my-library/
  test-point.ecadsym
  buffer.ecadsym
```

Use **Download example** for a working symbol, or copy the [example directory](../packages/web/public/examples/symbols), which contains [test-point.ecadsym](../packages/web/public/examples/symbols/test-point.ecadsym) and [buffer.ecadsym](../packages/web/public/examples/symbols/buffer.ecadsym).

Manage libraries under **Projects → Symbol libraries**. Choose **User libraries** or **Project libraries** in **Add library to**, then enter a name and upload files or a directory. The editor's **Symbols** menu contains grouped symbols and a search field that receives focus when opened. Library upload and configuration controls stay on the Projects page. File uploads default to "Imported symbols" for the user scope and "Project symbols" for a project. Directory uploads default to the directory name. Uploading to an embedded library with the same name adds symbols to that library.

The built-in library contains 49 symbols generated by [`@ecad/default-symbols`](../packages/default-symbols/README.md). It includes passive components, diode variants, bipolar and field-effect transistors, switches, power symbols, connectors, an operational amplifier, and RP2040, RP2350A, and RP2350B microcontrollers. The picker groups built-ins by component type and shows imported and project definitions under Custom symbols. Empty groups stay hidden. The package adapts KiCad library geometry and includes its source attribution and license. Run `pnpm run symbols:generate /absolute/path/to/output` to export the collection as standalone files.

Each library has an enable checkbox. Custom named libraries also have a remove button. Built-in symbols are an enabled user library by default and can be disabled. Choose a symbol, then click the drawing to place it. Disabling or removing a library affects the picker. Placed symbols keep their geometry and attributes.

To start an empty symbol, choose **New symbol** beside the project file list and enter a name. The app saves a new `.ecadsym` file and opens it in the borderless symbol editor. Repeated names create separate files. Empty symbols stay unavailable for placement until you add shapes.

To create a symbol from an existing drawing, select two or more drawing shapes, choose **Create symbol** in Attributes, and enter a name. The selection becomes one symbol and its definition appears in **Symbols**. The app saves it to the project's default symbol library when a project is open, or to the user library otherwise. Undo restores the original shapes while keeping the reusable definition.

Select a placed symbol and choose **Edit symbol** in Attributes to open its reusable definition. The editor uses the library that currently defines that symbol, including user libraries, named project libraries, and desktop directory libraries. Editing is available when the definition's storage is writable. Bundled definitions are read-only.

Changes save automatically. For user and directory libraries, **Save symbol** retries a failed save and **Back to schematic** saves before returning. Directory edits preserve the original filename and metadata. The editor refuses to overwrite a definition that changed externally. Future placements use the updated definition; existing placements keep their geometry and attributes.

## User and project configuration

User libraries apply to every project. Opening or creating a project keeps them available without copying their definitions into the project. The picker loads enabled user libraries in configuration order, then enabled project libraries. Later definitions replace earlier definitions with the same symbol ID, so project definitions take precedence. Built-in symbol IDs remain reserved. An unreadable directory library reports an error without hiding other libraries.

On the web, user configuration lives in localStorage under `ecad.user-config.v1`, independently of project data in the Origin Private File System. Uploaded libraries contain validated copies of their symbol files. Other open browser editors receive changes to user configuration. Uploading a directory copies its current contents; import changed files into a new library or remove the old library before reimporting.

On desktop, user configuration lives at `~/.ecad/config.json`. **Add library directory** opens the native directory picker and adds a directory source to the selected scope. The editor can only save directory sources that you chose with **Add library directory** or that are already in `~/.ecad/config.json`. **Reload libraries** rereads configuration and directory files. Uploaded or created symbols can also be stored as embedded definitions in the user config, without opening a directory first. Filesystem access stays in Electron's main process through the existing preload bridge. The main process validates every request from the editor before it touches files.

Project configuration lives in the drawing file's `symbolLibraries` field and survives saves, reopening, and source-file imports. Existing standalone project symbols remain in the manifest's `symbols` list and appear as the default "Project symbols" library. Project library settings stay outside drawing undo history. Desktop project directory sources may use absolute paths or paths relative to the project directory. Relative user directory sources resolve against the home directory. Both scopes accept paths beginning with `~/`.

A project file comes from whoever shared the project, so the desktop app treats its library paths as untrusted. A project library inside the project directory loads without a prompt. If its path leads outside the project, including through `..`, an absolute path, `~/`, or a symbolic link, the app asks before reading the directory or saving symbol edits there. The prompt shows the real directory after links are resolved. A directory you choose with **Add library directory** counts as allowed for the rest of that session, for any project that names it. The app remembers each allowed project and directory pair in `~/.ecad/approved-libraries.json`, never in the project. Untitled projects keep the answer until the app closes. If you choose **Don't allow**, the library reports an error. Reopening the project asks again, and choosing the directory with **Add library directory** allows it without reopening. Untitled projects cannot use relative directory paths until they are saved.

The user configuration has this shape:

```json
{
  "version": 1,
  "symbolLibraries": [
    {
      "id": "builtin",
      "name": "Built-in symbols",
      "enabled": true,
      "source": { "kind": "builtin" }
    },
    {
      "id": "my-parts",
      "name": "My parts",
      "enabled": true,
      "source": { "kind": "directory", "path": "~/symbols/my-parts" }
    }
  ]
}
```

An uploaded library uses `source: { kind: "embedded", symbols: [...] }`, where every array entry is a complete symbol file. A project stores the `symbolLibraries` array with its drawing data. Configuration supports at most 32 libraries per scope and 10 MiB of serialized data. Library IDs must be unique within their scope.

If browser storage is unavailable, imports remain usable in the open editor and the picker reports their temporary lifetime. Desktop config and project saves report write failures and keep the previous configuration.

## File structure

```json
{
  "format": "ecad-symbol",
  "version": 1,
  "units": "mm",
  "id": "custom.connector",
  "name": "Connector",
  "description": "Single connection point",
  "prefix": "J",
  "value": "1 pin",
  "shapes": [
    { "kind": "rectangle", "x": 0, "y": 0, "width": 2, "height": 2 },
    { "kind": "wire", "x1": -2, "y1": 0, "x2": -1, "y2": 0 },
    { "kind": "pin", "name": "IN", "number": "1", "x": -2, "y": 0 }
  ]
}
```

All fields above are required. `description` and `value` may be empty strings. Unknown fields are rejected to catch misspellings.

| Symbol field | Meaning |
| --- | --- |
| `id` | Unique stable ID, 1–64 characters: lowercase letter first, then lowercase letters, digits, `.`, `_`, or `-`. Use a namespace such as `custom.connector`. |
| `name` | Display name, 1–100 characters, not all whitespace. |
| `description` | Text shown in the picker, up to 500 characters. |
| `prefix` | Reference prefix, 1–16 characters: ASCII letter first, then letters, digits, or `_`. Instances receive references such as `J1`. |
| `value` | Default editable value, up to 100 characters. |
| `shapes` | Up to 256 primitives, described below. An empty array represents a symbol with no shapes yet. |

## Drawing primitives

Coordinates are relative to the symbol's placement origin `(0, 0)`. Positive X points right; positive Y points up. Dimensions are in millimetres and are preserved on import, without automatic resizing. Strokes default to 0.254 mm. Every primitive accepts an optional positive `lineWidth` in millimetres, up to 1000 mm. Symbols created from selections preserve their shapes' stroke widths; an instance's line width can be edited after placement.

| `kind` | Required geometry fields | Optional fields |
| --- | --- | --- |
| `wire` | `x1`, `y1`, `x2`, `y2`: line endpoints, including diagonal lines | None |
| `line` | `x1`, `y1`, `x2`, `y2`: endpoints at any angle | None |
| `rectangle` | `x`, `y`: centre; `width`, `height` | `rotation`: degrees counterclockwise, default 0 |
| `triangle` | `x`, `y`: bounding-box centre; `width`, `height`. The unrotated triangle points up. | `rotation`: degrees counterclockwise, default 0 |
| `circle` | `x`, `y`: centre; `radius` | None |
| `pin` | `x`, `y`: centre of a filled connection marker | `name`, `number`: strings, default to empty. `showName`, `showNumber`: optional booleans. `showLabels`: legacy boolean, default to true |

Every pin has a fixed radius of 0.254 mm (diameter 0.508 mm), including standalone pins and pins inside symbols. Pin size stays fixed when a symbol is fitted or its line width changes. Pin files specify their terminal position, optional name, optional number, optional lead `length` in millimetres, and optional `rotation` in degrees; `radius`, `width`, and `height` are not accepted for pins. New pins have a 2 mm lead pointing right. Select a pin to edit its Name, Number, Lead length, and Angle in Attributes. The lead and labels follow the pin when it moves or rotates. Wires connect only to its exposed terminal. Missing `length` keeps an older pin point-only, while zero explicitly removes a lead. Shift-click a pin to select it without starting a wire. Names sit beyond the lead toward the component body. Numbers sit above the lead. Both stay readable as the pin rotates. Numbers are text, so values such as "01" and "A1" keep their spelling. Names and numbers survive undo, saving drawings, and creating or saving symbols. Older files without these fields remain supported.

Set `showName` and `showNumber` independently on a pin to control its native labels. Each omitted field falls back to `showLabels`, then to `true`. For example, `showLabels: false, showNumber: true` shows only the number. Explicit independent fields take precedence over `showLabels`. These optional booleans work in version 1 symbol files, drawing pins, and symbol placement `childOverrides`. Attributes exposes them as Show name and Show number. Existing files need no migration. Set a pin's legacy `showLabels` to `false` to hide both labels when independent fields are absent. The pin keeps both values and remains available for wire connections. Built-in signal ground and supply symbols hide their pin labels. Battery terminal labels remain visible.

Add a `pin` wherever an external wire should connect. A `line` or decorative `wire` primitive alone does not define a terminal. SVG and images are not supported. Text shapes accept `text`, `fontSize`, `x`, `y`, `width`, `height`, and optional `rotation` in degrees. `horizontalAlign` accepts `left`, `center`, or `right`. `verticalAlign` accepts `top`, `middle`, or `bottom`. Alignment anchors the text box at `x` and `y` along its local axes. Omitted alignment keeps the box centered.

## Symbol references

Schematics and symbol files refer to library definitions by the library's scope and ID and the symbol's stable ID, stored as `definitionId`. Display names can change without breaking references. For example, a symbol file can include this placement in its `shapes` array:

```json
{
  "kind": "symbol",
  "library": { "scope": "user", "id": "builtin" },
  "definitionId": "resistor",
  "x": 0,
  "y": 0,
  "rotation": 90
}
```

`scope` is `user` or `project`. `id` identifies an entry in that scope's symbol library configuration. The default built-in library uses `user` and `builtin`; project symbol files use `project` and `project-symbols`. Rotation in symbol files uses degrees, while schematic drawing geometry uses radians.

Placements do not save the referenced definition's shapes. The editor resolves geometry and label styles from the library, so definition edits appear in existing placements. Schematics retain instance positions, rotations, attribute values, explicit stroke overrides, and `textPositions`. This optional object maps `name`, `reference`, and `value` to label anchors with `x` and `y` in millimetres relative to the symbol origin before rotation. New placements copy their initial text positions from the definition. Older drawings without a position use the library's default for that label. Drag any item on an unselected symbol to move the whole symbol. Select the symbol first, then drag a child to move it independently. Select a child on the canvas to edit its local coordinates, dimensions, text, pin fields or appearance in Attributes. A child at X = 0 and Y = 0 sits at the symbol center. Label positions survive saving, undo and redo, and moving or rotating the symbol. Nested placements accept optional `attributes` with `name`, `reference`, and `value`, optional `textPositions` in the same local coordinates, and an optional `lineWidth` override. The optional `textAlignments` object maps each label attribute to `horizontalAlign` and `verticalAlign` overrides. Each placement saves these overrides independently of the library definition.

The optional `childOverrides` object stores instance edits to individual children. Keys such as `shape:2` refer to a child's local ID. Attribute labels use `attribute:name`, `attribute:reference` and `attribute:value`. Each entry contains only changed fields, such as `x`, `y`, `fontSize`, `text`, `number` or `lineStyle`. Coordinates are relative to the symbol center before rotation. Override rotations use radians, matching drawing shapes. Nested placements preserve the same overrides. The library definition and other placements keep their original children.

Change Locked in Attributes or use Lock selection and Unlock selection in the toolbar to change the selected symbol or item. Mixed selections show an indeterminate checkbox. Every drawing item and nested placement accepts an optional `locked` boolean. Standalone items default to unlocked. Within a symbol, non-text children default to locked, while static text and attribute labels stay unlocked. An explicit lock value on a child or its instance override takes precedence. Child overrides accept the same field, including attribute labels. A child lock prevents local edits and follows the symbol when the whole symbol moves. Locked symbols and standalone items cannot be selected or moved until Select locked items is on in the toolbar. The flag never overrides a child lock. Unlocked children remain selectable when their parent is selectable, regardless of the flag. Locks survive project saves, symbol files and undo. The toolbar flag is an editor preference and does not change drawing history.

Library precedence chooses the definition for a new placement. Existing references keep their original library even when another library defines the same symbol ID. Missing or disabled libraries produce an error and retain the reference for later recovery. Circular references are rejected during resolution. Symbols can nest at most 32 levels and resolve to at most 65,536 primitive shapes.

Older schematics with inline symbol geometry remain readable. Saving migrates known built-in and embedded project definitions to references. Legacy symbols whose library cannot be identified retain their inline geometry.

Coordinates must be between -1000 and 1000 mm. Widths, heights, and radii must be between 0.01 and 1000 mm. Lines and wires must be at least 0.01 mm long. Rotation must be between -360 and 360 degrees. Every number must be finite.

## Import rules

- Each file describes exactly one symbol. The filename is for organization; the `id` identifies the symbol.
- Select at most 100 symbol files per import, totaling at most 1 MiB (1,048,576 UTF-8 bytes). The browser cache and an opened desktop directory each hold at most 100 custom symbols and 1 MiB of serialized symbol data.
- IDs must be unique within each library and cannot match built-in symbols (all IDs generated by `@ecad/default-symbols` are reserved).
- Duplicate IDs within one library are rejected, including when reimporting the same file. Different libraries may define the same ID. The last enabled definition wins, with project libraries loaded after user libraries.
- All selected symbol files are validated before any are added. Invalid files are reported by filename or directory path; duplicate conflicts report the symbol ID. Failed imports or directory reads leave the existing symbol list unchanged.
- Desktop saves refuse to replace existing files. If files change after loading, refresh the library before saving additional symbols.
- Multi-symbol library files are not accepted. Symbols already saved by the earlier importer remain available from the browser cache.

Older point-only pins also accept an optional `labelOffset` in millimetres. It sets the distance from the terminal center to the nearest name label edge. Positive values place names to the right, negative values to the left, before pin rotation. With an explicit offset, the name sits level with the terminal and the number sits above the lead, centered between the terminal and a body edge 0.5 mm before the name. Pins with a `length` compute label placement from their lead and rotation instead.

Rectangles, circles, and triangles accept an optional `filled` boolean. A filled shape uses the editor's opaque dark blue-grey body color behind its outline and text.
